## Glossary of Terms

The following definitions apply throughout all validation documents in this package.

| Term | Abbreviation | Definition |
|------|-------------|------------|
| 21 CFR Part 11 | Part 11 | Title 21 of the Code of Federal Regulations, Part 11 — FDA regulation governing electronic records and electronic signatures. Establishes requirements for trustworthy, reliable, and equivalent-to-paper electronic records. |
| Acceptance Criteria | — | Pre-defined conditions that must be met for a test case, deliverable, or system to be considered acceptable for its intended use. |
| Adverse Event | AE | Any untoward medical occurrence in a clinical trial subject, whether or not considered related to the investigational product. |
| Audit Trail | — | A secure, computer-generated, timestamped record that allows reconstruction of the course of events relating to the creation, modification, or deletion of an electronic record. Required by 21 CFR 11.10(e). |
| CAPA | CAPA | Corrective and Preventive Action — a systematic process for identifying, investigating, and resolving quality issues and preventing recurrence. |
| Case Report Form | CRF / eCRF | A printed or electronic document designed to record protocol-required information on each trial subject. Electronic CRFs (eCRFs) are the primary regulated records in an EDC system. |
| CDASH | CDASH | Clinical Data Acquisition Standards Harmonization — CDISC standard defining basic data collection fields for clinical trials. |
| CDISC | CDISC | Clinical Data Interchange Standards Consortium — organization that develops global data standards for clinical research. |
| Change Control | — | A formal process for documenting, reviewing, approving, and implementing changes to a validated system. Ensures changes do not adversely affect system compliance. |
| Clinical Data Management | CDM | The process of collecting, cleaning, managing, and archiving clinical trial data to produce a high-quality, reliable database for statistical analysis. |
| Clinical Data Management System | CDMS | A software application used to manage clinical trial data, including data entry, validation, query management, and export. An EDC system is a type of CDMS. |
| Configuration Management | CM | The process of identifying, controlling, and tracking system configurations to maintain integrity and traceability. |
| Corrective Action | — | Action taken to eliminate the cause of an existing nonconformity or other undesirable situation to prevent recurrence. |
| Data Integrity | — | The degree to which data is complete, consistent, accurate, trustworthy, and reliable throughout its lifecycle (ALCOA+ principles: Attributable, Legible, Contemporaneous, Original, Accurate, Complete, Consistent, Enduring, Available). |
| Data Lock | — | The final regulatory milestone after which no further changes can be made to clinical data without a formal unlock procedure. Precedes database unblinding and statistical analysis. |
| Data Freeze | — | An intermediate data protection step where data can only be modified through an authorized exception process. Precedes data lock. |
| Deficiency | — | A departure from a requirement, specification, or expected behavior identified during testing or inspection. |
| Design Qualification | DQ | Documented verification that the proposed design of a system is suitable for its intended purpose and compliant with applicable regulations. |
| Double Data Entry | DDE | A data quality technique where clinical data is entered twice by independent operators, and discrepancies are reconciled. |
| Electronic Data Capture | EDC | The computerized collection of clinical trial data in electronic format, replacing traditional paper-based data collection. |
| Electronic Protected Health Information | ePHI | Protected Health Information (PHI) that is created, stored, transmitted, or received in electronic form. Subject to the HIPAA Security Rule. |
| Electronic Record | — | Any combination of text, graphics, data, audio, pictorial, or other information representation in digital form that is created, modified, maintained, archived, retrieved, or distributed by a computer system. Defined in 21 CFR 11.3(b)(6). |
| Electronic Signature | e-Signature | A computer data compilation of any symbol or series of symbols executed, adopted, or authorized by an individual to be the legally binding equivalent of the individual's handwritten signature. Defined in 21 CFR 11.3(b)(7). |
| FHIR | FHIR | Fast Healthcare Interoperability Resources — HL7 standard for exchanging healthcare information electronically. |
| Functional Requirements Specification | FRS | A document specifying all functional requirements of the system, describing what the system must do. Serves as the basis for OQ test protocols. |
| GAMP 5 | GAMP | Good Automated Manufacturing Practice, version 5 — ISPE guideline for a risk-based approach to compliant GxP computerized systems. Defines software categories (1–5) and a scalable V-model lifecycle. |
| Good Clinical Practice | GCP | ICH E6(R2) — an international ethical and scientific quality standard for designing, conducting, recording, and reporting clinical trials. |
| GxP | GxP | A general abbreviation for Good Practice regulations and guidelines (GCP, GMP, GLP, GDP, etc.) that govern regulated industries. |
| HIPAA | HIPAA | Health Insurance Portability and Accountability Act — US federal law establishing national standards for the protection of health information. |
| HIPAA Security Rule | — | 45 CFR 164 Subpart C — establishes technical, administrative, and physical safeguards for the protection of ePHI. |
| ICH | ICH | International Council for Harmonisation of Technical Requirements for Pharmaceuticals for Human Use. |
| Installation Qualification | IQ | Documented verification that a system is installed correctly according to approved specifications, in the intended environment. |
| Intended Use | — | A documented statement describing the purpose of the system and the context in which it will be used. Drives the scope of validation. |
| Investigator | — | A person responsible for the conduct of a clinical trial at a trial site. If a trial is conducted by a team, the investigator is the responsible leader. |
| Least Privilege | — | A security principle requiring that users are granted only the minimum access permissions needed to perform their job functions. |
| Non-Repudiation | — | The assurance that the signer of an electronic record cannot deny having signed it. Required by 21 CFR 11.10(j). |
| Operational Qualification | OQ | Documented verification that a system operates according to its functional requirements specification across its anticipated operating ranges. |
| Operational Data Model | ODM | CDISC standard XML-based format for the interchange and archival of clinical trial data. |
| Performance Qualification | PQ | Documented verification that a system consistently performs as intended under real-world conditions, with actual users and data. |
| Predicate Rule | — | An existing FDA regulation (other than Part 11) that requires records to be maintained or submitted. Part 11 applies when predicate rule records are maintained in electronic form. |
| Preventive Action | — | Action taken to eliminate the cause of a potential nonconformity or other undesirable situation to prevent occurrence. |
| Protected Health Information | PHI | Individually identifiable health information held or transmitted by a covered entity or its business associate, in any form or medium. |
| Quality Assurance | QA | A systematic process of ensuring that all validation activities comply with established procedures, standards, and regulatory requirements. |
| Randomization | — | The process of assigning trial subjects to treatment groups using a chance mechanism to reduce bias. |
| Regulatory Compliance | — | The state of conforming to all applicable laws, regulations, guidelines, and standards that govern the use of a computerized system in a regulated environment. |
| Requirement Traceability | — | The ability to trace each requirement forward to its corresponding test case(s) and evidence, and backward to its regulatory source. Documented in the RTM. |
| Requirements Traceability Matrix | RTM | A document that maps each requirement to its source, test case, test result, and evidence. Demonstrates complete validation coverage. |
| Risk Assessment | RA | A systematic process for identifying, analyzing, and evaluating risks associated with a computerized system to determine appropriate validation scope and effort. |
| Role-Based Access Control | RBAC | An access control mechanism where system permissions are assigned to roles, and users are assigned to roles rather than receiving individual permissions. |
| Source Data | — | All information in original records and certified copies of original records of clinical findings, observations, or other activities in a clinical trial necessary for reconstruction and evaluation. |
| Source Data Verification | SDV | The process by which a monitor compares source data with corresponding data in the EDC system to verify accuracy and completeness. |
| Standard Operating Procedure | SOP | A documented procedure that prescribes how specific tasks or activities must be performed to ensure consistency and compliance. |
| System Owner | — | The individual responsible for the availability, support, and maintenance of a computerized system and for the security of the data residing on that system. |
| Test Case | TC | A documented set of conditions, inputs, actions, and expected results used to verify that a specific requirement or function works correctly. |
| Test Protocol | — | A formal document describing the scope, approach, resources, and schedule of intended test activities. Includes test cases. |
| User Requirements Specification | URS | A document specifying what the end users require from the system. Written in user language, it defines operational needs without prescribing technical solutions. |
| Validation | — | The documented process of demonstrating that a computerized system is fit for its intended use, operates correctly and consistently, and meets all applicable regulatory requirements. |
| Validation Master Plan | VMP | A high-level document that defines the scope, approach, resources, responsibilities, and schedule for all validation activities for a system or project. |
| Validation Summary Report | VSR | A document summarizing all validation activities, results, deviations, and conclusions. Provides the final determination of whether the system is validated for its intended use. |
| V-Model | — | A systems development lifecycle model where each development phase has a corresponding validation phase. Used in GAMP 5 for structured validation. |
| Wound Assessment | — | Clinical evaluation and documentation of wound characteristics (size, depth, tissue type, exudate) as part of a clinical trial protocol. |
